# Markdown Compression Brief (read this fully before editing)

Goal: make each assigned `.md` file **token-efficient** — strong compression with
**zero loss of meaning**. This is a rewrite for density, not a summary and not a deletion.

## Hard rules — these are verified mechanically, violations fail the build

A verifier (`scripts/verify_md_compression.py`) snapshots facts before/after and FAILS
if any of the following disappears. Preserve **byte-for-byte**:

1. **Every number**: measurements, percentages, `n=336`, `11.9pp`, scores, counts,
   Article/Law/Principle numbers (P1..P7, C1..C5, F1..F3), dates, line refs.
2. **Every fenced code block body** — do not reformat, re-indent, shorten, or "tidy"
   code, JSON, or diagrams. Copy them across untouched.
3. **Every table row and cell value** — you may tighten prose *around* tables,
   never inside them.
4. **Every heading** (its anchor slug must survive, so keep heading text stable —
   inbound `#links` depend on it).
5. **Every backticked identifier**: `module/path.py`, `function_name(...)`, config keys.
6. **Every relative link target** — must still resolve on disk.

## What to actually cut

- Filler and self-narration: "This document is intended for…", "As we can see…",
  "It is important to note that…", "In this section we will…".
- Ceremony: restating the heading in the first sentence; "Overview" paragraphs that
  only announce the doc's own structure.
- Repetition: the same rule/definition restated in 3 places → state it once, cross-reference.
- Marketing adjectives: powerful, comprehensive, seamless, robust, advanced.
- Bullet lists padded to look thorough where 2 lines carry the same content.
- Redundant transitional scaffolding between sections.

## What to keep even if it looks verbose

- Anything asserting a **fact, measurement, decision, ruling, or constraint**.
- Rationale that explains *why* a decision was made (this is the expensive knowledge).
- Falsifiers, invariants, pitfalls, permission boundaries, breach/enforcement rules.
- Karpathy quotes — **verbatim**, never paraphrased.
- Governance semantics: MUST/SHOULD/NEVER wording, HUMAN_CHECKPOINT, article bindings.

## Style target

Dense technical reference prose. Prefer tables and tight bullets over paragraphs.
Keep the existing document language (English) and existing heading hierarchy.
Aim for 35-55% byte reduction on verbose narrative docs; less is fine if the file is
already dense. **Never invent content, never add a "compressed by" note, never add
new sections.**
